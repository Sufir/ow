## 4. Что пришлось починить и почему

### 4.1. Скрипт — одна правка

**Что было не так.** В `SCHEMA.md` правило поля `closed` записано так: дата
стоит тогда и только тогда, когда статус `CLOSED` **или** `WONTFIX`. `STATE.md`
говорит, что правило внесено «в скрипт и в `SCHEMA.md`», и отдельно объясняет,
зачем в нём `WONTFIX`. В скрипте `WONTFIX` не было — он проверял только
`CLOSED`. Отсюда две дыры:

- `WONTFIX` без даты проходил молча — ровно тот случай, ради которого
  `WONTFIX` в правило и включали;
- `WONTFIX` с датой давал ложную ошибку.

**Почему чинился скрипт, а не данные.** Схема — источник истины о структуре
реестров, и в схеме правило записано верно. Ошибался код.

**Что изменено** — `rules/tools/registry.py`, функция `check()`, блок про `closed`:

```python
# было
if it.get("status") == "CLOSED" and not has_closed: ...
if it.get("status") != "CLOSED" and has_closed: ...

# стало
done = it.get("status") in ("CLOSED", "WONTFIX")
if done and not has_closed: ...
if not done and has_closed: ...
```

Тексты сообщений и комментарий приведены в соответствие; в комментарии
записано, откуда правка.

**Влияние на текущие данные — никакого:** в `issues.yaml` нет ни одной записи
`WONTFIX`. Ошибки до правки и после одни и те же (раздел 1).

**Проверено** семью синтетическими записями через `registry.check()`.
`WONTFIX` без даты, `CLOSED` без даты, дата при `OPEN`, дата при `DECIDED` —
ошибка. `WONTFIX` с датой, `CLOSED` с датой, `OPEN` без даты — ошибки нет.
Семь из семи, как ожидалось.

### 4.2. Данные — не правились. Четыре записи ждут решения

Валидатор здесь прав: дата закрытия стоит при незавершённом статусе.
Починить это можно двумя способами, и оба исключены:

- **перевести `status` в `CLOSED`** — верная правка, но статус issue —
  редакторское решение, ТЗ его трогать запрещает;
