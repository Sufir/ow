# CODE-05 — прогон реестров после P9 и сверка счётчиков

**Исполнитель:** Claude Code. **Автор задачи:** Claude (Cowork).
**Зачем:** в Cowork Linux-песочница недоступна, `registry.py` не запускается.
После P9 в реестры добавлены записи, отчёты в `rules/reports/` протухли.

**Рабочая директория:** `C:\YandexDisk\Oil Wars`
**Ничего вне `rules/` не менять.**

---

## Шаг 1. Прогнать реестры

```
docker run --rm -v "C:/YandexDisk/Oil Wars/rules/:/work" -w /work \
  python:3.12-slim sh -c "pip install --quiet pyyaml && python tools/registry.py all"
```

Ожидается `EXIT=0`. Если валидатор ругается:

- **чинить данные**, если нарушена схема из `registry/SCHEMA.md`;
- **чинить скрипт**, если правило валидатора само неверно;
- **не чинить молча ни то ни другое** — в отчёте написать, что именно
  поправлено и почему.

Формулировки правил, оценки `confidence` и статусы issue не трогать: это
редакторские решения, а не данные.

## Шаг 2. Выписать фактические счётчики

Из вывода скрипта, не из головы и не из `STATE.md`:

- число записей в каждом из семи реестров;
- разбивка `issues.yaml` по статусам;
- разбивка `numbers.yaml` по `match`;
- разбивка `terms.yaml` по статусам;
- разбивка `icons.yaml` по статусам;
- разбивка `baseline.yaml` по `status` и `confidence`.

**Правило проекта: статистику берём из скрипта, а не считаем руками.**
Ручной счёт в `STATE.md` уже ошибался дважды.

## Шаг 3. Проверить целостность ссылок текста

Это не делает `registry.py` — нужен отдельный проход по двум файлам:
`rules/reports/rulebook-draft.md` и `rules/reports/glossary-draft.md`.

1. **Перекрёстные ссылки.** Собрать все вхождения вида `(7.3.1)`, `— 8.4`,
   `см. 11.6` и проверить, что каждый такой номер существует как заголовок.
   Отчитаться числом: всего ссылок, битых столько-то, список битых.
2. **Плейсхолдеры иконок.** Собрать все `{ИМЯ}` и сверить с полем
   `placeholder` в `registry/icons.yaml`. Плейсхолдер, которого нет в реестре, —
   ошибка. Запись реестра, ни разу не встретившаяся в тексте, — тоже находка,
   но более мягкая: выписать отдельным списком.
3. **Emoji.** Сплошной поиск по обоим файлам. Их должно быть **ноль**
   (устав §10). Нашлись — выписать с номерами строк.
4. **Запрещённые слова `D-003`.** В теле правил не должно быть «дополнение»,
   «эррата», «FAQ», «в базовой игре». Искать с учётом словоформ.
   Служебные блоки в шапке черновика — не тело правил, их не считать.

## Шаг 4. Отчёт

Создать `rules/tasks/CODE-05-report.md`:

1. Вывод `registry.py all` целиком, как есть.
2. Таблица фактических счётчиков из шага 2.
3. Результаты четырёх проверок шага 3, каждая с числом и списком находок.
4. Что пришлось починить и почему. Если ничего — так и написать.

Ничего в тексте правил не править. Задача — измерить, а не исправить.
