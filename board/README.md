# map — реконструкция игрового поля Cthulhu Wars

Машиночитаемое описание оригинальной Earth Map базовой коробки для составов
3–5 игроков: полный список областей, нейминг, тип, принадлежность к материку
и бассейну, стартовые глифы, символы регионов и все смежности.
Схема — `SCHEMA.md`.

```
board/
├── SCHEMA.md        описание модели и всех полей
├── regions.yaml     27 областей оригинала (EN)          ← правится руками
├── edges.yaml       77 смежностей                       ← правится руками
├── configs.yaml     4 конфигурации + опубликованные инварианты ← правится руками
├── glyphs.yaml      стартовые глифы, СИМВОЛЫ РЕГИОНОВ, стартовые области,
│                   ориентиры ← правится руками
├── redesign.yaml    наши названия и соответствие оригиналу     ← правится руками
├── findings.yaml    находки MF-###                     ← правится руками
├── derived/         графы, матрицы, DOT                 ← генерируется, не править
└── geo/             эталонная география мира (master geometry) ← генерируется
```

## Где смотреть стартовые области

- **Машиночитаемо:** `glyphs.yaml` → `start_areas_redesign` (наши восемь фракций,
  привязка к ID областей по каждой стороне планшета) и `faction_glyphs`
  (глифы оригинала, по кому какая область).
- **Какой символ в этой области:** `board/reports/11-map.md`, раздел «Символы
  регионов» — таблица по каждой из четырёх раскладок; источник — `glyphs.yaml`
  → `region_symbols`.
- **Глазами:** `board/reports/11-map.md`, разделы «Стартовые глифы, напечатанные на
  поле», «Стартовые области наших восьми фракций» и «где стоят глифы в этой
  раскладке» — отдельным списком по каждой из четырёх раскладок.
- **Первоисточник и обоснование:** `rules/registry/factions.yaml`, поля `start_area`,
  `start_area_glyph`, `start_area_source` у фракций оригинала и `start_region`
  у наших. Здесь то же самое, но привязанное к областям карты.

Отчёт — `board/reports/11-map.md`, тоже генерируется.

## Как пользоваться

```
python tools/map.py all      # check + build + verify + report
python tools/map.py check    # только валидация YAML
```

Python на машине нет — гонять в Docker, как и `registry.py`:

```
docker run --rm -v "C:/YandexDisk/Oil Wars/rules/:/w" -w /w python:3.12-slim \
  sh -c "pip install --quiet pyyaml && python tools/map.py all"
```

## Что здесь считается истиной

Поле — два планшета, каждый с двумя сторонами («3 игрока» и «5 игроков»).
27 областей в `regions.yaml` — это не 27 клеток на столе, а весь набор,
из которого собирается любая из четырёх раскладок:

| | Левый планшет | Правый планшет | Итого |
|---|---|---|---|
| общие (6 океанов + Антарктида) | — | — | 7 |
| сторона «3» | 3 | 3 | +6 → **13** |
| сторона «3» + сторона «5» | 3 | 7 | +10 → **17** |
| сторона «5» + сторона «3» | 7 | 3 | +10 → **17** |
| сторона «5» | 7 | 7 | +14 → **21** |

Числа 13 / 17 / 21 названы прямо в рулбуке. Океаны на обеих сторонах одинаковы,
меняется только дробление суши, поэтому граф любой раскладки получается
фильтрацией одного общего списка рёбер по присутствию областей.

## Откуда взялась топология и почему ей можно верить

Смежности сняты машинно со слоёв `board/legacy/карта 5.psd` (`SRC-OW-MAP-PSD`):
в файле есть готовые маски по одной на область, маски снимались с вычитанием
вышележащих слоёв и с учётом склейки левого и правого краёв листа, смежностью
считалось касание масок после расширения на 3 пикселя при эталоне 2400×1203.
Длина касания записана в `edges.yaml` как `contact_px` — это доказательство,
а не геометрия.

Полученный граф сверен с величинами, опубликованными по **оригинальному**
полю (`SRC-BGA-GRAPH`, фотографии настоящих планшетов + `SRC-RB-NEW`).
`board/tools/map.py verify` прогоняет 21 проверку: число областей и океанов в каждой
раскладке, диаметры, пофамильные степени всех 13 областей стороны «3», полные
списки самых длинных пар во всех четырёх раскладках, число областей со
степенью 2 и 4 и разница в одно ребро между двумя раскладками на четверых.
Все 21 проходят. Отсюда `MF-001`: наша карта повторяет деление оригинала
один в один, и восстановленный граф можно считать графом оригинала.

## `board/legacy/карта 5.psd` — не трогать

По этому файлу один раз снята топология оригинала (`MF-001`), и на этом его
роль закончилась. Он **исторический источник, а не рабочий файл**: не открывать,
не править, не переименовывать слои, правок не предлагать (`MF-002` закрыта
именно так). Новое поле рисуется с нуля в векторе — `MF-017`.

`board/tools/mapgeom.py` читает этот PSD и тоже считается legacy: он нужен только
для замера старого референса. Новое поле меряется `board/tools/boardcheck.py`
по вектору.

## Геометрия

Решением от 2026-09-16 (`MF-007`) координаты и контуры **игровых областей**
в реестр не заводятся: здесь только топология с ограничениями. Это в силе.

Отдельно от этого с 2026-09-17 в `geo/` живёт **эталонная география мира** —
материки, острова, океан как чистая векторная геометрия из Natural Earth 1:50m
(`MF-014`). Это master geometry всего дальнейшего построения поля: одна основа
на обе версии карты, классическую и южно-полярную. Игровых регионов там нет.

Важно не путать два слоя:

| | `regions.yaml` / `edges.yaml` | `board/geo/world-base.geojson` |
|---|---|---|
| Что описывает | игровые области и смежности | географию Земли |
| Источник | слои `board/legacy/карта 5.psd` + сверка с оригиналом | Natural Earth 1:50m |
| Есть координаты | нет | да, WGS84 |
| Меняется ли этим слоем топология | — | **нет** |

Маски в PSD — это игровые области, а не материки, поэтому географию из них
брать нельзя: разбиение на регионы опиралось бы само на себя. Подробнее —
`geo/README.md` и `geo/world-base-report.md`.
