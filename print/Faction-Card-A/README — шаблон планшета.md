# Планшет фракции — шаблон

Два файла и папка с данными:

| Что | Зачем |
|---|---|
| `Шаблон.html` | вёрстка и оформление. Открывается в браузере и сразу показывает готовый планшет с демо-фракцией |
| `Сборка.py` | подставляет данные в шаблон и пишет `Планшет — <Фракция>.html` |
| `Данные/<Фракция>.json` | содержимое одной фракции |
| `decor/`, `barrel.png` | графика планшета |

Оформление живёт только в шаблоне, содержимое — только в данных. Скрипт между ними
ничего не решает, кроме вертикальной раскладки блоков свойств.

---

## Сделать новую фракцию

**Через генератор** — так быстрее:

1. Скопировать любой файл из `Данные/` под новым именем.
2. Заполнить поля (схема ниже).
3. `python3 Сборка.py` — соберёт все фракции. `python3 Сборка.py Клон` — только совпавшие по имени.
4. Открыть `Планшет — <Фракция>.html`, печатать Ctrl+P → A4 альбомная → 100 % → фон включить.

**Руками** — если нужен разовый планшет без данных:

1. Скопировать `Шаблон.html`.
2. Заменить содержимое между парными метками `#имя` своим. Метки не трогать.
3. Всё остальное в файле оставить как есть.

## Схема данных

**Кавычки в текстах — только “ ”** (`D-075`). С « », „ “ или прямыми " `Сборка.py`
планшет не соберёт и покажет, в каком поле ошибка.

```jsonc
{
  "название": "Глобал Петролеум",          // отображается прописными
  "логотип":  "Глобал Петролеум.png",      // файл из art/logos/
  "бочка":    "barrel-he3.png",           // необязательно: свой значок в бочке трека;
                                            // без поля — barrel.png (капля нефти)
  "декор": {                               // необязательно: фоновая картинка фракции
    "файл": "decor/bg-naa.png",            // уже окрашенный PNG с альфой
    "место": "колонка",                    // «колонка» — заполнить свободное место под
                                            // блоками левой колонки (по умолчанию);
                                            // или [x, y, ширина, высота] в мм планшета
    "прозрачность": 0.3,
    "затухание": "сверху" },               // необязательно: «сверху», «по краям»,
                                            // «по диагонали»

  "подготовка": {
    "регион":     "Европа",
    "очередь":    "03.0",         // две цифры до точки и дробная часть, D-053, D-060
    "нефть":      "8",
    "примечание": "1 фабрика под контролем и 6 рекрутов в стартовом регионе."
  },

  "блоки": [                                // нумерованные блоки левой колонки
    { "заголовок": "Создание боевого робота «Вихрь»",
      "шаги": ["...", "...", "..."] },
    { "заголовок": "Задачи на убийство",   // блок без нумерации: «текст» вместо «шаги»
      "текст": ["абзац"],
      "внизу": true }                       // необязательно: прижать к низу колонки (D-060)
  ],

  "свойства": [                             // средняя колонка, порядок сверху вниз
    { "заголовок": "Добыча",
      "фаза":      "Фаза получения ресурсов",
      "текст":     ["абзац", "абзац"],
      "отряд":     "Полковник",             // необязательно: к кому вести линию
      "притяжение": false,                  // необязательно: линия есть, но блок к отряду
                                            // не тянется и встаёт в общий поток (D-060)
      "смещение": 8 }                       // необязательно: ручная доводка после раскладки,
                                            // мм, плюс — вниз; берётся из зазора снизу,
                                            // зазоры не меньше 3 мм, первый блок не двигается (D-073)
  ],

  "отряды": [                               // таблица справа, три вида строк
    { "имя": "Рекрут", "группа": "Пехотинцы",
      "иконка": "Units/adept.png",
      "размер": "пехота",
      "количество": "6", "стоимость": "1", "сила": "0" },

    { "разделитель": true },                // розовая линия между группами

    { "сноска": "n — сила отряда равна числу ваших пехотинцев в игре.",
      "про силу": true }                    // true → розовым, как значение силы
  ],

  "оборот": {
    "лор": "абзац",
    "как играть": ["абзац", "абзац"],
    "как играть против": ["абзац"],        // необязательно: второй блок советов
    "иллюстрация": "Файл.png"              // необязательно: файл из art/illustrations/,
  }                                         // без поля — рамка-заглушка 52 × 52
}
```

**`группа`** ставится только у первого отряда группы — подпись растянется на всю её высоту.

**`размер`** — высота силуэта. Отражает реальный масштаб миниатюр, но сжато,
иначе строки таблицы разъезжаются:

| значение | мм | кто |
|---|---|---|
| `пехота` | 9,0 | рекрут, андроид |
| `офицер` | 10,5 | полковник |
| `машина` | 12,0 | боевые машины |
| `мех` | 12,5 | боевой мех |
| `робот` | 14,5 | боевой робот |

**`отряд`** в свойстве — это имя из поля `имя`, слово в слово. По нему рисуется линия-привязка.

**Символы регионов** пишутся в фигурных скобках: `{Q}` нефть, `{W}` огонь, `{E}` руда.
Внутри — буквы раскладки шрифта Oil Wars.

**Нефть как ресурс** — `{R}`, капля в кольце (ICON-001): «Заплатите 10{R}.».
Значок стоит вплотную к своему числу, без пробела; если пробел всё же
попал в данные, `Сборка.py` его уберёт. Цвет значка — всегда цвет текста,
в который он вставлен. Подпись «Запас: 8{R}» строка подготовки ставит сама,
в данных `нефть` — только число.

**Переменная сила** обозначается буквой `n`, расшифровка — строкой `сноска` под отрядом,
с `"про силу": true`. Если сила зависит от количества юнитов, пишется `n - 1`, `n + 1`.

Сноска всегда начинается с «n — » и говорит, чья это сила (§8.4 книги):

1. **Формула считает сам отряд** — «n — сила отряда равна …». Если таких отрядов
   больше одного, «n — сила каждого отряда равна …» («Абрамс 2220»).
2. **Формула считает, сколько таких отрядов в битве** — `n` здесь число, а не сила:
   «n — число отрядов этого типа в битве.», затем — что сила одна на группу отрядов
   этого типа, а не у каждого (машины Глобала). В таблице группой называется весь
   блок «Боевые машины», поэтому «этого типа» обязательно.
3. Добавка к формуле — отдельным предложением, числом: «С “Универсализацией” —
   ещё +1 за каждый “Рипо” М-3 в игре.», «Если на поле “Биг Текс” — ещё +1.»
4. Счёт — «числу», не «количеству» и не «сумме». «В игре» и «на поле» — разные
   термины (§3.4), берётся тот, что в оригинале. Исключения — «… не считаются.»

## Слоты шаблона

| Метка | Что внутри |
|---|---|
| `название` | текст в `<title>` и в шапке левой колонки |
| `логотип` | один тег `<img class="logo-wm">` |
| `бочка` | один тег `<img>` бочки у трека нефти; по умолчанию `barrel.png` |
| `подготовка` | три строки: регион, очередь и запас, примечание |
| `блоки` | нумерованные блоки левой колонки |
| `свойства` | блоки средней колонки |
| `отряды` | строки таблицы |
| `связи` | запасные линии-привязки |
| `иллюстрация` | картинка 52 × 52 на обороте или заглушка |
| `лор` | абзац на обороте |
| `как-играть` | абзацы советов на обороте |
| `против` | блок «Как играть против данной фракции» или ничего |

## Что подкручивать

Все габариты, кегли и цвета — в блоке `:root` шаблона, в миллиметрах и пунктах.
Рядом с каждым написано, на что он влияет. Числа с пометкой «синхр.» продублированы
в `Сборка.py` — менять парой.

Чаще всего нужны:

1. `--card-w` / `--card-h` — габарит. Ниже 170 мм по высоте не уходить: упирается
   таблица отрядов самой плотной фракции (Глобал Петролеум, 136 мм из 136).
2. `--bleed` — выпуск под обрез на лицевой стороне.
3. `--track-gap` — двигает шкалу нефти по горизонтали, `--track-y` и `--barrel-y` —
   по вертикали, внутри полосы: колонки от этого не сдвигаются. `--barrel-x` выводит
   бочку левее поля планшета. Ячейка 16,0 мм, вписанный круг 13.86 мм — под маркер
   14–15 мм (`D-064`, `D-070`). Координаты ячеек
   записаны в SVG числами: при смене размера цепочку нужно пересчитать целиком.
4. `--fs-*` — кегли. Взяты из оригинала и уже на нижней границе читаемости:
   уменьшать нельзя, увеличивать можно.
5. `--pink` — третий цвет: сила, разделители групп, линии-привязки.
6. `--c-icon` / `--c-stat` — колонка отряда и три числовые. Сумма с `--c-group`
   обязана давать `--col-table`. 29 мм — под «Моторизированный» в 9 pt (D-063).

## Что считает скрипт

Только запасную вертикальную раскладку средней колонки — на случай, если скрипт
шаблона не выполнится. Высоту блоков он оценивает по длине строк и ошибается
на несколько миллиметров, поэтому в браузере раскладку пересчитывает скрипт
шаблона по фактическим высотам (`D-055`):

1. блок, привязанный к отряду, тянется центром к подписи отряда, порядок сверху
   вниз сохраняется, зазор между блоками не меньше 3 мм;
2. колонка плотная (в среднем меньше 8 мм свободного на зазор) — притяжение
   не держится, свободное место делится поровну, иначе блоки слипаются парами;
3. не влезло — сначала поджимаются добавленные зазоры, затем сами зазоры;
4. осталось больше 12 мм — часть раздаётся между блоками.

Ручная правка `margin-top` в готовом файле больше не действует: скрипт его
перезапишет.

Всё остальное — прямая подстановка.

## Линии-привязки

Разметка содержит посчитанные линии, но скрипт в конце шаблона пересчитывает их
по фактическому положению текста: точка встаёт в 2 мм за последней буквой заголовка
свойства, линия кончается в 1 мм перед первой буквой подписи отряда (`D-055`).
Раньше конец стоял на фиксированной отметке, и длинные имена — «Абрамс 2220»,
«Зардоз», «Шредингер» — заходили под линию. Точность — доли миллиметра.

**Мелкий залом выпрямляется** (`D-066`). Если заголовок свойства и подпись
отряда разошлись по высоте меньше чем на 3 мм, скрипт сдвигает блок на этот
перепад за счёт соседних зазоров (не меньше 3 мм, первый блок не двигается),
и линия идёт прямо. Сдвинуть нельзя — линия всё равно прямая на уровне
заголовка, если он попадает в высоту подписи. После сдвига концы линии всегда
берут одну координату: остаток в доли миллиметра тоже даёт видимую ступеньку (`D-068`). Перепад от 3 мм остаётся заломом:
его видно явно, а не как брак.

Если скрипт не выполнится, напечатаются посчитанные линии. Больше от него ничего
не зависит.

## Печать

| | Лицевая | Оборот |
|---|---|---|
| Метки реза | нет | крестики по углам, от габарита планшета |
| Выпуск под обрез | 6 мм со всех сторон | нет |
| Размер печати | 252 × 182 мм | 240 × 170 мм по линии реза |

Рамки на обороте нет. Метки считаются формулой от `--card-w` и `--card-h`,
при смене габарита двигать их не нужно.
Метки — крестики: обе линии проходят через угол и заходят на 5 мм внутрь по
кромке. После отреза одной стороны у соседних углов остаются направляющие для
перпендикулярных кромок. Длины — `--crop-out` и `--crop-in` в правиле `.crop`.

## Открытые вопросы по содержанию

1. ~~**«Абрамс 2220» (Североамериканский Альянс)**~~ — решено `D-076`: сила `n`
   у каждого «Абрамса», сноска под ним; у «Биг Текса» своя `n` и своя сноска —
   как у Глобала, две расшифровки рядом со своими группами.
2. **«Зардоз» (Moon Systems)** — сила `0`: у него сила действительно 0.
   Боевой эффект — отдельное свойство «Киборг-убийца», а не сноска (`D-052`).
3. **Два разных `n` у Глобала** — `n - 1` и `n + 1` у машин означают число
   отрядов этого типа в битве (одно значение на группу), `n` у «Чёрного вихря» —
   стоимость давления на треке Судного дня (`D-065`). Каждое расшифровано
   своей сноской рядом со своей группой.

## Что ещё лежит в папке

Новый конвейер зависит только от `Шаблон.html`, `Сборка.py`, `Данные/`,
`decor/`, `barrel.png` и `barrel-he3.png` (бочка Moon Systems). Остальное можно удалить, когда не понадобится:

| Файл | Что это |
|---|---|
| `template.html`, `build.py` | прежний конвейер, заменён |
| `_faction-data.json`, `_back-text.json` | его данные, перенесены в `Данные/` |
| `variants.html`, `icons-header.png` | черновики по ходу работы |
| `Шрифты — варианты.pdf`, `Подготовка — варианты.pdf` | сравнения вариантов оформления |
| `ПРОМПТЫ — декор планшета.md` | промпты на декор. §6 закрыт: угол нарисован вектором |

В `decor/` используются только `corner-a.png` и `side-rail.png`. Рядом лежат
`corner-tr-1.svg` и `corner-tr-2.svg` — два варианта правого верхнего угла,
второй стоит в шаблоне. Остальное — отвергнутые заготовки и исходники генерации.
