# SPEC-BOARD — спецификация физического игрового поля

Статус: **черновик v0.9, рамочный.**

**Это не жёсткие требования.** Это фундамент, на который опираются дальнейшие
работы, и вектор, куда двигаться. Подход agile: увидели результат — вносим
коррективы. Любое число здесь можно поменять по ходу реализации, если
реализация показала, что оно неудачное.

Одно условие: правка не молчком. Поменял число — строка в журнале изменений
внизу, с причиной. Иначе через месяц никто не вспомнит, почему было 55,
стало 40 и что из этого правда.

Область действия: физическая карта «Нефтяных войн» — носитель, размер,
форма областей, пригодность под миниатюры. Топология (кто с кем граничит)
этим документом **не меняется**: источник истины — `regions.yaml` /
`edges.yaml`, подтверждено `MF-001`.

Всё в мм и см², если не сказано иное. Числовые пороги откалиброваны
по замеру существующей карты — он вынесен в приложение А как справочный
материал; сама существующая карта считается референсом, а не объектом
доработки. Инструмент замера — §10.

### Швов нет. Разрезов нет. Склейки краёв нет

Три слова, которые всплывают при каждом касании карты, потому что они описывают
**оригинал**, а не наш компонент. Зафиксировано, чтобы не всплывали снова:

| Термин | Что это в оригинале | У нас |
|---|---|---|
| **Шов** | стык двух планшетов: поле оригинала из двух кусков, они кладутся рядом, линия стыка идёт по Северной Атлантике между Востоком Южной Америки и Западной Африкой; семь областей печатаются кусками на обоих планшетах | **нет и не планировалось.** Решение № 1: четыре отдельных цельных поля |
| **Разрез** (меридианом) | область упирается в левый край листа и продолжается у правого; так напечатаны Север Тихого и Индийский океан, по два куска и четыре стрелки-указателя | **нет.** Решение № 12: край листа — настоящий край карты |
| **Склейка краёв** | правило рулбука с. 9 «the Areas on the far right of the Map connect directly to those on the far left because the Earth is round» | **нет.** Правило из книги уходит; проверено, что оно не создаёт ни одной смежности — все 77 рёбер реализуются внутри листа |

Описание оригинала остаётся в `configs.yaml` → `meta.seam` и `meta.meridian`:
это baseline, он верен и правке не подлежит. К нашему полю не применяется.

Решение № 1 закрывает `MISS-023` в части «сколько частей»: двух двусторонних
половин, как в оригинале, у нас не будет. Смешанные раскладки на четверых
обеспечиваются не складыванием, а двумя отдельными готовыми полями. Текст
правил §1.1 и §2.1 написан по оригиналу («2 части, каждая двусторонняя»)
и **подлежит правке** под этот компонент — отдельной задачей, не здесь.
Той же задачей снимается абзац про склейку краёв.

## 2. Полотно

| Параметр | Значение |
|---|---|
| Носитель | баннер или неопрен, цельное полотно, без сгибов и швов |
| Целевой размер | **900 × 550 мм** (4950 см²) |
| Желательный коридор | 850–900 × 500–550 мм; небольшие оправданные отклонения приемлемы |
| Абсолютный предел | **1000 × 600 мм** — выходить нельзя категорически |
| Текущий факт | 934 × 468 мм (короткая сторона ниже желаемого коридора) |
| Рабочий исходник | 300 dpi на итоговый размер: при 900 × 550 это 10 630 × 6 496 px |
| Технологическое поле | 10 мм по периметру: подгиб и люверсы у баннера, прошивка у неопрена. В это поле не заходит ни один регион |
| Запас на обрез | 5 мм сверх технологического поля |

Целевой размер взят по верхней границе желаемого коридора: печать цельным
полотном ничем не ограничивает пропорцию, а +13 % площади к нынешним
934 × 468 достаются бесплатно. Каждые −50 мм по длинной стороне снимают
≈ 275 см², то есть ≈ 14 см² с каждой области.

Про разрешение: широкоформатная печать обычно принимает 150 dpi, но
рабочий исходник держим 300 — уменьшить всегда можно, вернуть обратно нет.

**Раскладка полотна на листы не нормируется и не считается** — решение Alek
от 2026-09-16: печать типографская, цельным полотном. Ни в этом документе,
ни в любом другом по карте форматы офисной бумаги не упоминаются.

**Требования §6 заданы в абсолютных мм и см²,** потому что выведены
из физического размера миниатюр. Увеличение полотна их не смягчает —
оно только облегчает их выполнение.

## 4. Соединения

### 4.1 Обязательные

Полный список — `edges.yaml` (77 рёбер), матрицы по раскладкам —
`derived/MC-*.md`. Ребро входит в раскладку, если в неё входят обе области.

**Реестр — источник истины.** Картинка подгоняется под него, а не наоборот.

Длина общей границы объявленного ребра:

| Длина касания | Как трактуется |
|---|---|
| **< 8 мм** | **отказ**: за столом граница не читается, соединение спорное |
| 8–25 мм | предупреждение `NARROW`: узкое место, проверяется глазами |
| ≥ 25 мм | норма |

Нижний порог задан не круглым числом, а географией: через Панамский
перешеек проходят настоящие узкие соединения, и требование 25 мм отвергало
бы связи, которые есть в оригинале. Поэтому 8 мм — жёсткий пол, а полоса
8–25 мм — повод посмотреть, а не повод переделать.

Для сравнения: на референсной карте ниже пола оказалась одна пара —
Западная Африка — Аравийский полуостров, 7,2 мм через Синай.

### 4.2 Запрещённые

**Любая пара, которой нет в `edges.yaml`, не должна соприкасаться.**
На стороне «5» это 154 пары из 210.

Требование: **несмежные области разделены не менее чем 12 мм**, и разделяет
их третья область или край полотна, а не пустое поле.

Сверка идёт по раскладкам: пара сравнивается только там, где обе области
лежат на одном полотне. Без этого родитель стороны «3» и его дети стороны
«5» дают ложные пересечения — на одном полотне они не встречаются никогда.

Места, где на референсной карте зазор меньше 12 мм, перечислены
в приложении А — это подсказка, за какими стыками следить при отрисовке,
а не список дефектов к исправлению.

### 4.3 Самое узкое место карты — Панамский перешеек

Здесь сходятся шесть обязательных рёбер и одно обязательное **не**-ребро.
Ошибка на пару миллиметров ломает граф, поэтому участок рисуется первым
и проверяется отдельно.

Обязаны быть смежны: Центральная Америка — Запад Южной Америки (`ME-005`),
Центральная Америка — Восток Южной Америки (`ME-004`), Центральная Америка —
Север Атлантики (`ME-027`), Центральная Америка — Север Тихого (`ME-028`),
Запад Южной Америки — Север Тихого (`ME-048`), и два океана напрямую:
Север Атлантики — Север Тихого (`ME-074`) — вода проходит в разрыве
перешейка между островками, рулбук это отмечает особо.

Обязаны **не** соприкасаться: Запад Южной Америки — Север Атлантики.
Сейчас они разведены на 8,5 мм при требуемых 12 — самый тесный зазор
на карте. Рядом ещё два узких места: Центральная Америка — Восток Южной
Америки (16,4 мм касания) и Центральная Америка — Запад Южной Америки
(19,9 мм), оба в полосе предупреждения §4.1.

## 5. Две метрики размера области

Площадь сама по себе ничего не говорит: длинный узкий регион большой
площади бесполезен под фигуры. Поэтому два числа.

### 5.1 Area (A)

Площадь области внутри границы, см². Служебная метрика: по ней виден баланс
полотна, требования на ней не строятся.

### 5.2 Usable area (U) — рабочая площадь

**Правило вписывания (решение № 5).** Фигура может заходить на границу.
Она считается стоящей в регионе, если в регионе не менее **85 %** площади
её подставки. Геометрически это значит: центр фигуры радиуса `r` отстоит
от границы не менее чем на **0,585 · r** — и может быть даже снаружи
границы, если та выпуклая.

Отсюда отступы от границы до центра фигуры:

| Фигура | ⌀ | 80 % внутри | **85 % внутри (норма)** |
|---|---|---|---|
| Пехотинец, полковник, энграмма | 25 | 6,1 мм | **7,3 мм** |
| Боевая машина, мех | 40 | 9,8 мм | **11,7 мм** |
| Жетон «Военная фабрика» | 40 | 9,8 мм | **11,7 мм** |
| Боевой робот | 60 | 14,8 мм | **17,6 мм** |

**U = площадь множества точек, где может стоять центр пехотинца**, то есть
эрозия области на 7,3 мм. Единица измерения — см².

Что в U **не** вычитается: подписи, глифы, рисунок. Фигура стоит поверх
печати, и это нормально; на геометрию поля подписи не влияют (решение № 11).

Что вычитается: технологическое поле 10 мм по периметру полотна.

### 5.3 Производные

| Обозначение | Что это | Как считается |
|---|---|---|
| **N_пех** | сколько пехотинцев реально ставится | жадная укладка: центры внутри U, расстояние между центрами ≥ 26 мм |
| **N_маш** | то же для ⌀40 | центры не ближе 11,7 мм к границе, между центрами ≥ 41 мм |
| **N_роб** | то же для ⌀60 | центры не ближе 17,6 мм к границе, между центрами ≥ 61 мм |
| **U/A** | КПД формы | отношение рабочей площади к полной |

Фигуры между собой не пересекаются — зазор 1 мм. На границу области заходить
можно, друг на друга наезжать нельзя.

**Про «отношение площади к периметру».** Классическая компактность 4πA/P²
здесь не работает: периметр задаётся изрезанностью берега, которая на игру
не влияет. Гладкий берег и рваный при одинаковой U ведут себя за столом
одинаково. КПД формы меряется как **U/A**, периметр не нормируется.

**Минимальная ширина** отдельным числом не задаётся — она зашита
в определение U. Рукав уже 14,6 мм даёт нулевой вклад в U автоматически.

## 6. Числовые требования к области

| Метрика | Минимум | Норма | Крупные |
|---|---|---|---|
| **U, см²** | **≥ 55** | **≥ 85** | ≥ 150 |
| **N_пех** | **≥ 10** | **≥ 14** | ≥ 20 |
| **N_маш** | **≥ 3** | **≥ 5** | ≥ 8 |
| **N_роб** | **≥ 1** | **≥ 2** | ≥ 3 |
| U/A | ≥ 0,55 | ≥ 0,65 | ≥ 0,70 |
| A, см² — *справочно* | *≈ 90* | *≈ 140* | *≈ 250* |

**Площадь A в вердикт не входит.** §5.1 говорит, что требования на ней
не строятся, и это должно оставаться правдой: регион с A = 87 и U = 58
проходит минимум, а регион с A = 76 и U = 37 — нет. Числа по A даны
как ориентир при эскизе, когда U ещё не посчитана.

Дополнительно:

- **Стартовые области: N_пех ≥ 14.** На расстановке там уже стоят военная
  фабрика и шесть пехотинцев (один — поверх фабрики), и туда же приходит
  противник. Стартовые области — §8.3.
- **Связность рабочей зоны:** крупнейший связный кусок U даёт **≥ 60 %**
  всей U. Иначе область распадается на площадки и перестаёт читаться
  как одно целое.
  **Исключение — области-рамки** (область, обходящая полотно по периметру;
  сейчас такая одна, Северный Ледовитый океан, решение № 12). Для них
  связность меряется по `A` — непрерывности заливки, — а не по `U`.
  Обоснование: требование написано против распада области на зрительно
  не связанные площадки. Рамка нарисована одной непрерывной полосой
  с одной подписью и читается как одно целое, а где именно внутри области
  стоит фигура, правилам безразлично.
- **N_роб ≥ 1 — отказной критерий.** Боевой робот есть у каждой фракции,
  и правила не запрещают ему находиться где угодно. Область, куда робот
  физически не встаёт, — брак.

### Откуда числа

- **N_пех ≥ 10** — стартовая расстановка (фабрика + 6 пехотинцев, один
  поверх фабрики) плюс три чужих отряда.
- **N_пех ≥ 14 (норма)** — крупная битва: 6 пехоты + 3 машины + робот
  у одной стороны и несколько отрядов у другой. Ровно такой стек
  наблюдался в симуляции: Южная Азия держала 8 отрядов и фабрику
  (`out/10-playthrough.md`).
- **N_маш ≥ 3** — фабрика ⌀40 плюс две боевые машины: жетон фабрики
  меряется по той же мерке, что машина.
- **A ≈ 90** — следствие: при КПД 0,6 это даёт U ≈ 55. Ориентир, не критерий.

Ограничения сверху нет: океан или большой материк могут быть заметно
крупнее нормы, и это нормально.

**Рекомендация по балансу.** Игровая ценность области от её размера
не зависит: океан вмещает столько же отрядов, сколько нужно, и лишняя
площадь там пропадает. На референсной карте перекос трёхкратный —
шесть океанов держат 55 % полотна при средней рабочей площади 286 см²,
пятнадцать областей суши — 45 % при средних 89 см². Разумный ориентир
для новой компоновки: **примерно 47 / 53 в пользу суши**, тогда средняя
область суши сама выходит на норму, а океаны остаются крупными.

## 7. Край полотна

**Меридиана нет, разрезов нет, стрелок нет** (решение № 12). Край полотна —
это настоящий край карты: по периметру идёт рамка Северного Ледовитого океана,
и левый край листа с правым не соединяется, потому что это одна и та же
область, обходящая полотно кругом.

Требования:

- **ни одна область не разрезана краем полотна.** Область, напечатанная
  двумя кусками, — брак;
- стрелок-указателей «продолжается с другой стороны» на полотне нет;
- края полотна касается только рамка Северного Ледовитого. Ближайшее к краю
  кольцо суши — Запад и Восток Северной Америки, Скандинавия, Северная Азия —
  граничит с рамкой, но до края не доходит. **Центральная Америка и Европа
  до рамки не доходят вовсе:** первую замыкают Запад Северной Америки и два
  океанских сектора, вторую — Скандинавия, Северная Азия и сектор Севера
  Атлантики (`EXPERIMENT-POLAR.md` §3.4);
- рамка несимметрична (решение № 13): торцы 60 мм, длинные края 10 мм.

Что отсюда следует для книги: правило склейки краёв (`SRC-RB-NEW`, с. 9)
и объясняющий его абзац из текста уходят. Проверено, что правило не создаёт
ни одной смежности — все 77 рёбер реализуются внутри листа, — поэтому
механика от его снятия не меняется.

Описание меридиана оригинала остаётся в `configs.yaml` → `meta.meridian`
как baseline и правке не подлежит.

## 8. Что печатается на поле помимо областей

### 8.1 Метка Глобал Петролеум

Глифов фракций на нашей карте нет: стартовый регион записан текстом
на планшете фракции (`MF-009`). **Единственное исключение — Глобал
Петролеум** (в оригинале Yellow Sign, «Король в жёлтом»), решение № 10.

**Логотипов фракций на карте нет ни одного** (Alek, 2026-09-16). Это
относится и к метке Глобал Петролеум: она не логотип фракции, а отдельный
знак со своим сюжетом — **капля нефти внутри вихря**, перекличка с боевым
роботом «Чёрный вихрь».

Логотипы фракций живут на акриле (`07. Жетоны-логотипы`) и на планшетах;
на полотно карты они не попадают.

Исполнение метки — задача на арт, здесь не нормируется: метка печатается
в рабочей зоне области, фигура стоит поверх неё, на геометрию поля
она не влияет.

Размещение берётся из `glyphs.yaml`, запись `MG-002` (достоверность HIGH,
проверено по обеим сторонам оригинала):

| Поле | Область с меткой |
|---|---|
| `MC-3P` | Европа |
| `MC-4P-A` | Европа |
| `MC-4P-B` | Европа |
| `MC-5P` | Европа — **не Скандинавия** |

На стороне «5» Европа делится на Европу и Скандинавию, и метка остаётся
в Европе. Это и есть причина, по которой метка нужна именно этой фракции:
у остальных семи на планшете написан самый узкий регион, имя которого
однозначно («Западная Африка», «Южная Азия», «запад Северной Америки»),
а у Глобал Петролеум написано «Европа» — имя, которое на стороне «5»
можно прочитать и как материк целиком.

Метка занимает место в рабочей зоне области, но из U не вычитается:
фигура может стоять поверх неё.

### 8.2 Символы регионов

Второй и последний тип знака на полотне. Три символа: **капля `Q`**
(`ICON-032`), **пламя `W`** (`ICON-033`), **вагонетка `E`** (`ICON-034`),
глифы шрифта `Templates/Fonts/Oil Wars.ttf`. Со знаком стартового региона
(§8.1) они не имеют ничего общего: тот один и про расстановку, эти три
и про задачи фракций.

От них зависят семь задач: три у Глобал Петролеум («разместить нефтяную
вышку в регионе, отмеченном символом …») и четыре у Братства Сингулярности
(по одной общине в регионе с каждым символом плюс одна в регионе без
символов). Решение рисовать их на поле — `D-043`; размещение — `D-046`.

**Размещение повторяет оригинал один в один.** В оригинале это три Spellbook
Glyph фракции Yellow Sign — Dragon, Thorns и Chevron, — напечатанные прямо
на карте Земли. Снято с растра обеих сторон настоящего поля
(`SRC-CW-MAP-SCAN`), имена глифов — `SRC-WIKI-YS`.

Закон размещения: **символ идёт по материку.**

| Наш знак | Оригинал | Материки | Областей на «3» | на «5» |
|---|---|---|---|---|
| капля `Q` | Dragon Glyph | Северная и Южная Америка | 2 | 5 |
| пламя `W` | Thorns Glyph | Европа и Азия | 2 | 5 |
| вагонетка `E` | Chevron Glyph | Африка и Австралия | 2 | 4 |

Пофамильный перечень — `glyphs.yaml` → `region_symbols`; собранная разбивка
по каждой из четырёх раскладок — `out/11-map.md`, раздел «Символы регионов».
`tools/map.py check` следит, что у каждой области суши кроме Антарктиды ровно
один символ, что у океанов и Антарктиды символа нет и что дети области стороны
«5» наследуют символ родителя.

**Что это значит для полотна.** Место под знак нужно в шести областях
на стороне «3» и в четырнадцати на стороне «5» — то есть почти везде, где
есть суша. Знак печатается в рабочей зоне области и **из U не вычитается**:
фигура может стоять поверх него, ровно как у метки §8.1.

**Регион без символа есть всегда** — шесть океанов и Антарктида, семь областей
в любой раскладке. Четвёртая задача Братства выполняется только там. Это
не наша особенность: в оригинале четвёртый собор The Ancients ставится в ту же
воду и по той же причине.

## 9. Фон под фигурами

Рабочая зона — место, где стоит пластик, и работает она как подложка,
а не как иллюстрация:

- светлота в рабочей зоне **25–55 %**: темнее — чёрный низ миниатюры
  сливается, светлее — карта теряет тон арт-библии;
- без мелкого высокочастотного рисунка: силуэт фигуры читается на любом
  участке рабочей зоны;
- цвет области отличается от соседних настолько, чтобы граница читалась
  при фигурах, стоящих на ней вплотную и заходящих на неё;
- «интересная» графика — рельеф, города, техника, текстура — уходит
  к границам и в рукава.

Общий принцип: **центр области спокойный, детали по краям.**

## 10. Как проверять

**Новое поле проверяется по вектору** — решение `MF-017`, Alek 2026-09-18.
Источник истины по геометрии поля — `board-<раскладка>.geojson` в миллиметрах
полотна; пороги §4 и §6 заданы в мм и см², поэтому сравнение прямое:

1. Каждая область — отдельный `Feature`, `properties.id` из `regions.yaml`.
2. Рабочая площадь `U` и вписанный круг — эрозия полигона на отступ фигуры.
3. `N_пех` / `N_маш` / `N_роб` — жадная укладка по карте расстояний:
   точка максимума, фигура, гашение окрестности радиусом (⌀ + 1 мм).
4. Смежность — **общая граница** двух полигонов; её длина сверяется
   с `edges.yaml`.
5. Несмежные пары — минимальное расстояние между полигонами, порог 12 мм.

Вектор снимает целый класс ложных срабатываний растрового замера — см.
«Про мусор в масках» ниже.

### Инструмент

Для нового поля — **`tools/boardcheck.py`** (читает GeoJSON). `map.py`
проверяет топологию по YAML.

### Legacy: замер psd-черновика

Ниже — методика, которой снят замер **старой референсной карты**
`Карта/карта 5.psd`. Она остаётся только для этого файла; новых артефактов
не касается, и сам psd-черновик правке не подлежит (`MF-002`).

1. Каждая область — отдельный слой-маска в PSD (группы «Материки База»,
   «Океаны База», «3 игрока»).
2. Маска снимается с вычитанием вышележащих слоёв группы; работа
   на уменьшении 1:4 от 300 dpi (≈ 0,34 мм на пиксель).
3. Карта расстояний до границы (`distance_transform_edt`) даёт U как
   площадь множества «расстояние ≥ 7,3 мм» и вписанную окружность.
4. N_пех / N_маш / N_роб — жадная укладка, как в п. 3 выше.
5. Смежность — касание масок после расширения на 3 px.
6. Несмежные пары — минимум карты расстояний одной маски по другой.

Это делает **`tools/mapgeom.py`** — геометрия по PSD со сверкой смежностей
с тем же YAML.

```
python tools/mapgeom.py measure     # замер -> registry/map/derived/geometry.json
python tools/mapgeom.py adjacency   # смежности из масок против edges.yaml
python tools/mapgeom.py check       # PASS/FAIL по §4 и §6
python tools/mapgeom.py report      # out/12-mapgeom.md
python tools/mapgeom.py all
```

Полезные ключи: `--psd` — другой файл карты; `--inside 80` — смягчить
правило вписывания; `--target 900x550` — пересчитать замер на целевой
габарит полотна, не перерисовывая карту; `--scale` — точность замера.

Запуск в Docker, как `registry.py` и `map.py`:

```
docker run --rm -v "C:/YandexDisk/Oil Wars:/w" -w /w/.agents python:3.12-slim \
  sh -c "pip install --quiet pyyaml psd-tools numpy scipy pillow && \
         python tools/mapgeom.py all"
```

Возвращает код 1, если есть отказы по §6 или нарушения топологии —
годится как гейт перед сдачей итерации.

Таблица `LAYER_MAP` в начале скрипта связывает имена слоёв с ID областей
реестра. Переименуют слой — правится там, в одном месте.

**Про мусор в масках.** Скрипт отбрасывает связные куски мельче 1 см²
и печатает их списком. Это не придирка: на референсной карте обрывок
маски в 0,54 см² давал ложную смежность Африки с Северным Ледовитым
океаном, а крошки у Панамы показывали зазор 0,3 мм там, где на самом деле
8,5 мм. Любой исходник, из которого снимается замер, должен состоять
из чистых масок — иначе цифры врут, причём в сторону паники.

Обе ошибки — артефакты растра, и это вторая причина, по которой новое поле
меряется по вектору: там общая граница либо есть и имеет длину, либо её нет.
